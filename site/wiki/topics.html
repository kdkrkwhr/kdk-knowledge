    • 칸반 검색·상태 필터의 전역 상태 공유 — 역할별 검색 입력은 따로 저장하지만 탭 전환 후 필터가 섞일 수 있다는 코드상 판단(실행 확인 아님, P2).

    • desk-brief의 선택적 PWA 입력과 cron 대체 — 날씨·뉴스는 출퇴근 PWA 데이터 폴더의 JSON을 먼저 시도하고 없으면 Hermes cron 출력으로 대체한다. PWA 파일은 선택적 입력이라 설치·실행 의존성이 아니다.
    • local-first는 완전 오프라인이 아님 — CLI 인증을 이용하므로 프롬프트와 작업 내용이 모델 서비스로 전송될 수 있다. 원격 사용자 인증이 없어 공개 프록시 노출을 피해야 하며 읽기 전용 CLI 설정도 OS 샌드박스가 아니다.
    • 공개 데모와 로컬 서버의 경계 — HTTPS Pages에서는 mock 자료로 장면을 보여 주고, 실제 프로필·칸반·로그는 루프백 로컬 서버에 연결했을 때만 흐른다. 데모 수치를 개인 작업 성과로 읽지 않는다.
    • 기본 로컬 저장과 선택적 네트워크 기능의 경계 — 중심 기록은 브라우저 로컬이지만 공인 IP 조회·Google Sheet 전송·통근·뉴스는 설정과 사용자 동작에 따라 외부 요청을 보낸다. 둘을 동일하게 '완전 오프라인'으로 설명하지 않는다.
    • 루프백 바인딩·CSRF 요청 경계 — 로컬 도구 목적에 맞게 루프백 접근만 허용하고 Host·Origin·CSRF 토큰을 검사한다. 다중 사용자 서비스로 확장하려면 인증·권한 경계를 새로 설계해야 한다.
    • 문자열 접두사 경로 검사의 취약점 — /api/file-preview의 허용 경로 검사가 정규화 경로의 문자열 접두사만 비교해 실제 포함 관계와 달라 루트 밖 텍스트를 읽을 수 있다. 경로 객체 기준 포함 검사로 고쳐야 한다(P1).
    • 에이전트 표시 이름 해석 순서 — area.json/office.json 설정값 → Discord 연결 이름 → SOUL.md 이름 → CLI 프로필 alias → 프로필 ID 순. default 프로필의 자료 루트는 Hermes 홈 자체다.

    • engine/game_api.py transition 함수 — 기존 상태·명령·실행 문맥을 받아 TransitionResult(결과·다음 상태·변경 여부·이벤트)를 반환. 명령 형식·접근 범위 검사 후 엔진 명령 분배. 파일 저장은 직접 하지 않는다.

    • web/store.js (IndexedDB saves 저장소) — 플레이어 상태를 리비전 비교로 갱신, 플레이어·그림 데이터를 별도 키로 관리하고 교체 시 같은 트랜잭션 사용. 웹 구현에 한정.
    • web/worker.js (Pyodide Worker) — Pyodide를 준비해 Python 코어와 규칙 데이터를 브라우저에 적재, 메시지를 받아 transition을 호출하고 결과·상태·뷰를 JavaScript로 반환.
    • 두 호출자가 같은 게임 규칙 진입점을 공유 — 브라우저 Worker(Pyodide)와 Anna Worker의 입출력 처리가 같다는 주장이 아니라 진입점(transition)이 같다는 관찰. 웹 저장(IndexedDB)을 Anna 영속화로 일반화하지 않는다.
    • 상태 전이와 저장 결정의 분리 — 공통 규칙 계산과 호스트별 저장 책임을 분리하고 실행 입력을 주입한다. 설계 이유는 공개 근거로 확정할 수 없다.
    • 재시작 실패 표시와 중복 전달 방지 — 끊긴 실행을 실패 상태로 표시하고 채널 메시지의 작업 식별자로 이미 전달된 응답을 재전송하지 않는다. 재검토 가능한 상태를 남기는 경로이지 모든 오류 회복 보장은 아니다.
    • 진화 방향 선택은 사용자에게 — 레벨만으로 진화하지 않고 활동 조건을 채운 뒤 사용자가 시점과 세 방향 중 하나를 고른다. AI는 설명·외형 제안만 보탠다.
