    냉정한 기술 평가

    평가일: 2026-10-28 · 근거 커밋: 8ff191956a0a8a7746f511810a798754375903e2. 공개 소스의 정적 평가이며 실제 운영 결과나 개인의 기여 범위를 확정하지 않는다.

    • 구조·설계 — 보완 필요 1분 스케줄과 외부 API 호출·Redis 적재가 분리돼 있지만 적재 키 설계가 공항별 결과를 보존하지 못한다. MainScheduler.java 18–22행 RealTimeService.java 92–104행
    • 구현 품질 — 위험 반복문에서 받은 apiData 대신 공항 설정 data를 저장하고, 모든 항목에 같은 timestamp 키를 사용한다. 반복 저장이 앞 값을 덮어써 수집 결과가 기대한 실시간 주차 정보가 아닐 수 있다. RealTimeService.java의 minuteScheduleF, 92–104행
    • 운영 준비 — 위험 수집 실패를 빈 catch가 삼켜 스케줄 로그가 정상 종료처럼 보일 수 있다. 실제 운영 여부는 알 수 없지만 이 코드 경로는 실패 감지를 막는다. RealTimeService.java 106–108행
    • 유지보수 — 보완 필요 XML 태그를 직접 꺼내는 함수가 필수 노드 부재를 먼저 검사하지 않아 외부 응답 형식 변경 시 원인을 찾기 어렵다. RealTimeService.java 40–46행

    좋은 점: 스케줄·수집·응답 API의 시작점은 찾기 쉽다. 개선 우선순위: P1 — 실제 apiData를 공항·주차장별 키로 저장하고 예외를 기록·전파해 잘못된 캐시와 조용한 수집 중단을 막는다.

    데이터 수집 경로

    MainScheduler는 1분 간격 fixedDelay로 RealTimeService.minuteScheduleF를 호출한다. 서비스는 로컬 JSON의 공항 코드를 순회하며 외부 주차 API XML을 읽고 주차장명·전체면수·점유면수 등을 파싱한다. 이 API 호출에는 설정된 키가 필요하지만 이 문서는 키나 결과 데이터를 공개하지 않는다. 원본: `src/main/java/com/kdk/scheduler/MainScheduler.java` 원본: `src/main/java/com/kdk/service/RealTimeService.java`

    구현에서 확인한 제약

    파싱한 apiData를 순회하지만 현재 Redis 저장 호출에는 apiData가 아니라 입력 JSON의 data.toJSONString()이 전달된다. 또 스케줄 메서드의 예외 catch는 비어 있다. 따라서 주차 잔여석이 Redis에 정확히 저장된다고 단정할 수 없다. 원본: `src/main/java/com/kdk/service/RealTimeService.java`

    /api/kakao GET 컨트롤러는 Redis 수집 결과 대신 classpath의 test.json을 읽어 JSON으로 반환한다. 이 API가 실시간 주차 조회와 연결됐다고 설명하지 않는다. 원본: `src/main/java/com/kdk/controller/KakaoSkillRestController.java`

    기술 범위

    Gradle은 Spring Boot와 데이터 관련 의존성을 정의한다. 실제 API 응답·Redis 저장·카카오 연동은 설치나 실행 없이 확인할 수 없다. 원본: `build.gradle`

    연결해서 읽기

    MSA Architecture와는 별도의 Spring 실험이다.

    확인 범위와 미확인 사항

    위 구현 설명은 표시한 커밋의 파일에서 확인한 사실과 정적 해석이다. 현재 배포·운영 상태, 실행 성공, 실제 사용량, 개인 선택 이유와 기여 범위는 확인하지 않았다.
