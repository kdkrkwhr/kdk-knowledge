# AI 기능을 서비스에 연결한 경험

**출처 구분:** 본인이 제공하고 공개를 확인한 경력 설명입니다. 회사의 공식 경력 증명이나 공개 코드의 독립 검증 결과를 뜻하지 않습니다. 비공개 이력서 원본·내부 코드·운영 데이터는 포함하지 않습니다. **기준일: 2026-11-09.**

## 백엔드에서 AI 기능으로 확장한 경험

상담 기능과 도메인 문서 검색, 모델 학습·서빙을 다루며 AI 기능을 기존 서비스에 연결했습니다. 모델 호출뿐 아니라 데이터 입력, 검색, 응답 전달과 저장 같은 백엔드 흐름을 함께 살펴봤습니다.

실무 경험은 본인 제공 설명이며, 개인 프로젝트의 공개 코드와는 근거를 구분합니다. 내부 데이터명·규모, 모델 세부 구성과 운영 인프라는 공개하지 않습니다.

## RAG와 상담 응답 연결

도메인 문서를 검색해 모델 응답에 활용하는 RAG 기능을 개발했습니다. Spring AI를 활용한 연동과 스트리밍 응답을 다룬 경험이 있습니다.

검색 기능과 생성 기능을 나누어 보면 어떤 단계에서 결과가 달라졌는지 설명하기 쉽습니다. 관련 경험을 다음 흐름으로 정리합니다.

1. 서비스가 사용할 질문과 입력 데이터를 구성합니다.
2. 관련 문서를 검색하고 모델에 전달할 근거를 구성합니다.
3. 검색 결과를 모델 입력에 연결합니다.
4. 생성된 응답을 서비스의 응답 방식에 맞춰 전달합니다.

이 흐름은 경험을 이해하기 위한 일반화된 설명입니다. 특정 서비스의 내부 아키텍처나 전체 처리 절차를 그대로 옮긴 것은 아닙니다.

## Dense·sparse 검색과 저장소 전환

Dense·sparse 검색을 통합하고 검색 저장소를 전환하는 업무를 경험했습니다. 검색 방식을 바꿀 때는 새 기능의 품질뿐 아니라 기존 서비스와의 연결도 확인해야 합니다.

평가에서는 서로 다른 질문을 구분합니다.

- 기존 방식과의 비교: 같은 입력에서 결과가 얼마나 일치하는가?
- 검색 품질: 필요한 문서가 후보에 포함되고 적절히 정렬되는가?
- 답변 품질: 검색된 근거를 활용한 답변이 질문에 맞는가?
- 운영 조건: 응답 시간과 비용, 변경 후 확인할 항목은 무엇인가?

검색 전환의 일치율은 전체 AI 서비스의 정확도와 다릅니다. 평가 기준과 대상이 다른 결과를 하나의 성능 숫자로 합쳐 설명하지 않습니다. 이 문서에서는 내부 평가 수치와 데이터셋은 공개하지 않습니다.

## LoRA 학습과 추론 서빙

도메인 데이터를 활용한 LoRA 학습과 vLLM 기반 추론 서빙을 경험했습니다. 학습 결과를 만드는 것과 서비스에서 해당 결과가 적용되는지를 확인하는 일은 이어지는 별도의 단계입니다.

관련 경험은 학습 입력, 모델·어댑터와 버전, 서비스가 사용하는 출력 형식을 연결해 정리합니다. 모델이나 어댑터가 바뀌면 무엇을 비교하고 어떤 출력이 기대되는지 설명할 수 있어야 합니다.

- 데이터 구성과 검증 관점
- 모델과 어댑터를 구분하는 기준
- 서빙 환경에서 적용된 결과의 확인
- 서비스에서 사용하는 출력 형식
- 변경 전후 결과를 비교할 테스트

이 목록은 경험을 정리하는 관점이며, 모든 항목이 자동화됐거나 운영 품질이 외부 검증됐다는 주장은 아닙니다.

## 개인 프로젝트: AI 표현과 확정적인 규칙 분리

개인 프로젝트 노트버디에서는 AI가 담당하는 표현과 코드로 확정해야 하는 게임 규칙을 구분합니다. 보상·능력치·타이머 같은 상태 변화는 코드에서 관리하고, AI는 캐릭터의 대화와 표현을 담당하도록 구성했습니다.

생성과 저장을 구분하고, 저장소 어댑터와 조건부 갱신·멱등성 처리를 다룬 경험도 연결할 수 있습니다. 생성형 기능을 적용할 때도 데이터 저장과 상태 변화는 일반적인 소프트웨어 검증의 대상입니다.

[노트버디 문서](notebuddy.md)는 확인한 공개 커밋과 정적 검토 범위를 별도로 제시합니다. 해당 문서가 모든 배포 환경의 동작을 검증하거나 회사 프로젝트의 구현을 증명하는 것은 아닙니다.

## AI 개발 경험을 설명하는 방식

기술을 나열하기보다 담당한 단계를 분명히 하려고 합니다. 검색을 개선한 경험, 모델을 학습한 경험, 추론 서버에 적용한 경험은 각각 다른 역할과 검증을 요구합니다.

기능이 동작한 사례뿐 아니라 무엇을 확인했고 무엇이 미확인인지 함께 남깁니다. 공개된 도구나 문서를 참고했다는 사실과 이를 직접 구현·운영했다는 사실도 구분합니다.

멘토링에서 다룬 프롬프트 설계와 AI 코딩 규칙은 [멘토링 경험](mentoring-experience.md)에 따로 기록했습니다. 실무 RAG·모델 서빙 경험을 교육생 프로젝트에서 그대로 수행한 것처럼 연결하지 않습니다.
