# AI 기능을 서비스에 연결한 경험

**출처 구분:** 본인이 제공하고 공개를 확인한 경력 설명입니다. 회사의 공식 경력 증명이나 공개 코드의 독립 검증 결과를 뜻하지 않습니다. 비공개 이력서 원본·내부 코드·운영 데이터는 포함하지 않습니다. **기준일: 2026-11-09.**

## 검색과 생성의 연결

도메인 문서를 검색해 모델 응답에 활용하는 RAG 기능을 다뤘습니다. 검색 결과를 구성하고 정렬하는 과정과 이를 모델 입력에 연결해 서비스 응답으로 전달하는 흐름을 살펴봤습니다.

검색 방식이나 저장소를 전환할 때는 다음 항목을 구분해 평가합니다.

- 기존 결과와의 일치 여부
- 필요한 문서의 검색 여부
- 검색 결과를 활용한 답변의 적절성
- 응답 시간과 운영 비용

하나의 수치로 AI 서비스 전체의 정확성을 설명하지 않으려고 합니다.

## 모델 학습과 추론 서빙

도메인 모델 학습과 추론 서빙 경험이 있습니다. 이 영역은 내부 데이터와 서버 구성을 공개하기보다, 학습 데이터 검증, 모델·어댑터 버전 관리, 출력 형식과 모델 변경 시 비교할 테스트를 중심으로 정리합니다.

## AI 표현과 코드로 확정하는 규칙

개인 프로젝트 노트버디에서는 AI가 담당하는 표현과 코드로 확정해야 하는 게임 규칙을 구분합니다. 보상·능력치·타이머 같은 상태 변화는 코드에서 관리하고, AI는 캐릭터의 대화와 표현을 담당하도록 구성했습니다.

[노트버디 문서](notebuddy.md)는 공개 구현을 확인한 커밋과 정적 검토 범위를 별도로 제시합니다. 그 문서가 모든 배포 환경의 동작을 검증하거나 회사 프로젝트의 구현을 증명하는 것은 아닙니다.
