# 백엔드 설계와 운영 경험

**출처 구분:** 본인이 제공하고 공개를 확인한 경력 설명입니다. 회사의 공식 경력 증명이나 공개 코드의 독립 검증 결과를 뜻하지 않습니다. 비공개 이력서 원본·내부 코드·운영 데이터는 포함하지 않습니다. **기준일: 2026-11-09.**

## 기존 계약을 유지하는 서비스 전환

기존 서비스를 새로운 환경으로 전환할 때는 기존 요청·응답 계약과 인증 방식이 유지되는지부터 확인합니다. 외부에 유지해야 할 인터페이스와 변경할 내부 구현을 나누고, 기존 동작과 비교할 검증 기준을 마련합니다.

## 캐시와 원본 데이터

리뷰·콘텐츠 API를 다루면서 캐시와 원본 데이터의 관계를 고민했습니다. 조회 성능뿐 아니라 원본 변경 시 캐시를 언제 갱신하거나 제거할지, 갱신 실패 시 어떤 데이터가 보일지도 함께 고려합니다.

## 이벤트와 동시성

이벤트 처리에서는 누락, 중복 요청, 동시 변경을 서로 다른 문제로 나눠 봅니다. 구현 이후에도 실패·재시도와 함께 로그, 모니터링, 배포와 롤백 방법을 확인합니다.

특정 테스트 수치만으로 서비스 전체의 안정성을 설명하기보다 어떤 환경에서 무엇을 검증했는지 기록합니다. 공개 소스를 읽고 확인한 사실과 실행으로 검증한 결과도 구분합니다.
